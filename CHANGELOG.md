# Changelog

Version history for the DealNews Blog Card Editor extension, newest first, moved verbatim out of `CLAUDE.md` (only the joining words "Currently at", "Before that," and the semicolons between versions were dropped, one version per bullet). References in these entries to a section "below" now point to the files in `docs/`: see the table in `CLAUDE.md`.

- `2.39.2` (as of 2026-11-25) — Creator Pick cards keep the blue creator pill when the CMS link plugin rewrites the link. The pill used to be the creator link itself (`<a class="cp-pill" style="…">`); when the plugin rewrites a link it adds `vendor`/`brand`/`category`/`landing_url` and drops `title`, `data-iref` and `style`, and the `style` held the pill's whole look, so the pill vanished (the `cp-pill` class survived, so the sort bar and "more" toggle kept working). `cpPillHTML()` now puts the pill style on a `<span class="cp-pill">` and only the name inside the link (`style="color: inherit; text-decoration: none;"`); the face image sits outside the link so the layout holds if the link loses its style. A rewritten link now shows at worst the name in the site's link colour inside the pill. `findCardLinks()` finds creator links with `a.cp-pill, .cp-pill a`, so cards pasted before this change still read. The page scripts need no change (they read `.cp-pill` for its text and `img`). Known side effect: the creator link still loses its `data-iref` whenever the plugin rewrites it; only the look is protected, and the Article tab's iref audit/fix can find the link again. Cards already pasted into articles keep the old markup until regenerated. Hand-patched earlier in cms-block-editor's copy of the card code (see the handoff note).
- `2.39.1` (as of 2026-11-25) — fixed the Creator Pick sort bar script breaking once it went through the CMS editor: `cardSortScript()` called `chip(chips, 'All picks', '', '')`, and the CMS body editor reads two `''` on one line as wiki-style italics and saves `<i>, </i>` into the script, which is a syntax error. The page script runs as one `<script>` block, so the "more" buttons on the cards stopped working too. The call is now `chip(chips, 'All picks', String(), null)`; the same value as before, with no `''` pair. Found on /features/creator-picks/black-friday/. Cards already pasted into articles carry the broken line and need regenerating (or that one line edited). Rule for page scripts: never put two `''` on one line.
- `2.39.0` (as of 2026-11-25) — Find offers: new **Creator** box takes a creator's page link (`…/creators/Andy-Frank/184.html`) or just the ID, several separated by commas, and brings in everything that creator picked (`findCreatorIds()`, sent as `creator_id`). The creator page itself lists only the first 20 picks; the content API returns all of them (Andy: 186 live), including picks where the creator is the second creator on the offer (the API names only the first one, so those rows read "pick by" the other creator). `creator_id` takes a comma list and combines with words, category, facet, vendor and "include expired" (probed 2026-11-25; an unknown ID returns nothing). Rows now show "pick by {name}"; "Hottest first" now also sends `sort=hotness` to the API (`findParams()`, `findState.sortSent`) so the first page is the hottest of all matches, not of the first 30 loaded (changing the sort re-runs the search when more pages are unloaded); a line above the results says whose picks and how many match in all; text that is not a link or number gets a warning instead of a search.

- `2.25.4` (as of 2026-10-06) — fixed reordering cards in the Article tab leaving blank space at the top of the list. The reorder step re-appended every surviving card to the end of its container (`appendChild`), which hoisted all recognized `.bu-card` elements past any non-card content in that container (whitespace, or a malformed card missing its `.bu-card` wrapper, which `findCardElements()` never sees) and left that content stranded at the top. Reordering is now slot-based: a placeholder comment marks each surviving card's current position, the cards are detached, then dropped back into those same positions in the new order — so non-card content keeps its place and cards only swap among their own slots. Still per-container, still gated on `canReorder && reordered`. Verified with a mock-DOM simulation (orphan block + 3 cards + a second container; plain reorder, reorder with a removal, and swaps in both containers).

- `2.25.2` (as of 2026-10-01) — changed the Expired-group move (`removeAndRegenerate()`) to insert newly-moved cards at the TOP of the existing Expired section instead of appending them at the end: a freshly-expired card is the one most likely to need a glance next, and appending meant the section grew oldest-first with every new arrival buried under an ever-taller pile of older ones. Implemented via a single `anchor = expiredContainer.firstChild` captured once before the move loop (not re-read per card, which would reverse the order), then `expiredContainer.insertBefore(el, anchor)` for each moved card in `articleCards` order — inserting each new card immediately before that same fixed anchor places them above the pre-existing section content while preserving the moved cards' own relative order (first-moved stays topmost-of-the-new-arrivals, not last). Verified via a mock-DOM simulation: 3 pre-existing cards + 3 newly-moved cards produced `[New1, New2, New3, Old1, Old2, Old3]`. See "Expired group" below.
- `2.25.1` (as of 2026-10-01) — fixed `removeAndRegenerate()`'s `toRemove` set independently re-deriving "should remove" from `c.status === 'expired' || 'deleted'`, in addition to `c.flagged`, which silently removed every expired/deleted-status card on regenerate regardless of whether the user actually flagged it — including a card explicitly marked `moveToExpiredGroup` (expired status is exactly why it was being moved, so it got swept into `toRemove` and deleted outright before the move loop ever ran, since `toMoveToExpired`'s `!toRemove.has()` guard excluded it) and any `keepDespiteExpired` ("Keep") card that also happened to have that live status. `toRemove` is now built from `c.flagged` alone — flagging (via the per-card 🚩, `flagExpired()`, `flagAllExceptKept()`, or "Flag All for Removal") is the single source of truth for removal, matching what `toggleFlag()`/`toggleMoveToExpiredGroup()`'s mutual-exclusion already assumed; status-based auto-removal without flagging was never a documented behavior and directly contradicted the Expired-group and "Keep" features. Verified via a mock-state simulation (flagged + unflagged-but-expired + moveToExpiredGroup-and-expired + active cards) confirming only the actually-flagged card lands in `toRemove` and the moveToExpiredGroup card now correctly lands in `toMoveToExpired` instead. See "Flagging for removal" below.

- `2.20.1` (as of 2026-08-14) — the Live Feed tab was removed from the extension entirely: `generateLiveFeedHTML()`, `fetchDealNewsOffers()`, `buildStaticSnapshotHTML()`, `renderLiveFeedOut()`, `copyLiveFeedHTML()`, the `DEALNEWS_API_AUTH` constant, the `pane-live`/`tab-live` markup, and the `https://api.dealnews.com/*` `host_permissions` entry were all deleted from `sidebar.js`/`sidebar.html`/`manifest.json`; `setTab()`'s tab array dropped `'live'`. The standalone `index.html` (already a verbatim, independently-maintained copy of this same generator) is now the only place this tool lives — nothing was ported or changed there (see "Live Feed Generator" below).
- `2.20.0` (also 2026-08-14) — Live Feed was a hybrid design instead of purely live, for SEO: `generateLiveFeedHTML()` fetches `api.dealnews.com` once at generation time (requires the new `https://api.dealnews.com/*` `host_permissions` entry) and bakes a real, static `.bu-card` snapshot (`buildStaticSnapshotHTML()`) into the output ahead of the `<script>` tag, so crawlers that don't run JavaScript see actual offer content immediately; the live-refresh script then replaces that snapshot with fresh results for real visitors, or leaves it in place if the refresh fails or returns nothing (see "Live Feed" below). If the generation-time fetch itself fails, generation falls back to a live-refresh-only snippet (`snapshotFailed: true`) rather than erroring out. `index.html` (the standalone generator) was ported to match.
- `2.19.0` — Find & Replace on the Article tab is now a two-step preview-then-apply flow instead of an immediate blind replace: "Replace All" became "Find Matches" (`previewArticleFindMatches()`), which lists every match with ~40 characters of surrounding raw HTML and a per-match checkbox (all checked by default) instead of writing anything yet; a new "Apply to Selected" (`applySelectedFindReplacements()`) then rewrites `articleOriginalHTML` using only the checked matches, rebuilding the string in one pass over stored offsets rather than repeated `.replace()` calls (which would shift later matches' positions). Motivation: the common case is swapping a month/year in a header, but that same text often also appears incidentally in body copy, and a blind replace-all couldn't tell those apart — showing raw-HTML context around each match lets a human see "this one's in an `<h2>`" vs. "this one's in a `<p>`" and uncheck accordingly, without teaching the code anything about document structure.
- `2.18.0` (as of 2026-08-13) — added a "Flag All Except Kept" button to the Article tab (`flagAllExceptKept()`) so an editor can flag every loaded card for removal in one click without also having to un-flag each intentionally-expired ("Keep") card by hand; unlike `flagExpired()` (which only flags cards whose live DatoCMS status is expired/deleted, minus Keep cards), this flags every card regardless of status, minus Keep cards — the two buttons answer different questions ("what expired" vs. "what am I clearing out"), so it's a new function alongside `flagExpired()`/`setAllFlags()`, not a merge into either.
- `2.17.0` (as of 2026-08-07) — offer descriptions now preserve list formatting and links instead of being flattened to plain text: `extractDastText()` (plain-text-only) was replaced with `dastNodeToHTML()`, which converts DatoCMS structured text to real HTML (see "Offer description formatting" below); `generateHTML()`'s description wrapper changed from `<p>` to `<div>` since it can now legitimately hold a `<ul>`, and the Article tab's card parser was updated to match that container by class token instead of tag name so it still finds it either way.
- `2.16.0` added a plain-text Find & Replace to the Article tab (see "Find & Replace" below), so a header typo or a month reference can be fixed without leaving the tab or bouncing through the Processor tab; card titles/callouts/CTA text refresh to match without losing flags, status, or reorder progress, and a mismatched before/after card count is flagged rather than silently trusted.
- `2.15.0` added `iref-append` tracking attributes to each generated card's image/title/button links (`site-widget-card-blog-{blog content ID}-{offer legacy ID}-{image|title|button}`, see "Generated HTML" below), fed by a new Blog Content ID field (Edit sub-view) and `fetchOffer()` now reading the offer's own `legacy_id`; a warning banner in the HTML sub-view calls out when the ID is missing rather than silently emitting incomplete tracking data.
- `2.14.0` merged the Configure, Preview, and HTML tabs into one Configure tab with an internal Edit/Preview/HTML sub-nav (see "Configure sub-tabs" below), since all three already operated on the same `offers` state and Preview already cross-linked to HTML. `setTab()` now only knows the four remaining top-level tabs; a new `setSubTab()` handles the internal switch, re-rendering Preview/HTML on switch exactly as the old top-level tabs did.
- `2.13.5` removed the "Inspect" tab: it was a standalone DatoCMS field diagnostic (`inspectOffer`) built to unblock the Auto Cards feature, but Auto Cards was itself removed in `2.13.4` and nothing else depended on it. Deleted `inspectOffer`, `resolveLinkedIds`, `formatLinkedItem`, `fetchItemTypeApiKey`, and `looksLikeDatoId` — confirmed via search that each was called only from within this tab; `datoHeaders()` and `resolveLegacyId()`, which it also used, stay put since the Configure tab depends on both.

Deleted `fetchAutoCards`, `buildAutoCardHTML`, `renderAutoCardOut`, `setAutoCardLayout`, `copyAutoCardHTML`, `resolveLegacyIdForModel`, `isOfferExpired`, `withRetry`, `mapWithConcurrency`, and their state (`autoCardLayout`, `autoFetchedOffers`) — all confirmed used only within that tab, not shared with anything still in the extension.
- `2.13.3` fixed Live Feed's images looking blurry: it was picking `Medium` (75px) from the API's `images` object and upscaling it to fill the 200px card image box, so the size priority now starts at `XL` (250px), the first size at or above the display box (see "Live Feed" below).
- `2.13.2` fixed Live Feed's `api.dealnews.com` calls returning `400 Missing Authorization header`: the request needs an `Authorization: DN <apiKey>` header (a custom scheme, not Bearer), which isn't visible anywhere in the request URL — found by loading the failing request's URL directly to read the JSON error body, then diffing against a working `blog-slider` request's actual headers (see "Live Feed" below).
- `2.13.1` fixed the Live Feed widget rendering nothing on a published page: `generateLiveFeedHTML()`'s inner script now builds cards via DOM APIs instead of concatenated HTML-tag strings, since DealNews's save pipeline was regex-scanning raw article HTML for `<img src="...">` patterns and mangling that literal text sitting inside the script's JS source, silently breaking it (see "Live Feed" below).
- `2.13.0` added a 9th "Live Feed" tab that generates a `<div>+<script>` snippet fetching live from DealNews's own `api.dealnews.com` content API in the visitor's browser (`generateLiveFeedHTML`) — unlike Auto Cards' snapshot, this stays live after the HTML is pasted, discovered by reverse-engineering `blog-slider`'s own network request and confirmed viable by testing that a `<script>` tag actually executes on a published article page (it does not in the CMS's own preview) (see "Live Feed" below).

- `2.10.5` fixed Auto Cards still returning 429s after `2.10.4`'s concurrency throttling: the real cost was total request *volume* (a `fetchOfferStatus()` call per over-fetched candidate, up to 150 per fetch), not just concurrency, so `fetchAutoCards()` now computes each candidate's active/expired status from data already in the list response (`isOfferExpired()`) instead of a second per-candidate request, and every remaining request goes through `withRetry()` for exponential backoff on 429 (see "Auto Cards" below).
- `2.10.4` fixed Auto Cards returning 429s on larger fetches by throttling its batches with `mapWithConcurrency()` instead of a bare `Promise.all` — a real improvement, but insufficient on its own since DatoCMS's limit is a rate quota, not a concurrency cap.
- `2.10.3` fixed Auto Cards potentially pulling in offers scheduled to publish in the future: `fetchAutoCards()` now filters out anything whose `requested_publish_datetime` is still ahead of now before sorting/status-checking, since DatoCMS's own publish status doesn't reflect that field (see "Auto Cards" below).
